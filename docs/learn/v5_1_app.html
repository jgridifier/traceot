Shipped: TRACE V5.1. Approved by the owner on 2026-11-05 ET: "Yes, ship V5.1: open the working-paper skeleton and app on the passed V5.1 gate, sealed holdout untouched." Docs only; every number is quoted from an existing repo file. Indices 9600–9619 stay sealed; no holdout was run.
Linear-mean only. V5.1 was validated on a simulator whose mean is linear. Verbatim from PREREG_V5_1 §7:
The simulator's mean is linear, so a linear location fit is the correct family by construction. A PASS shows that v5's mixture object works once the location model is right; it does not show robustness to non-linear means. That needs its own pre-registration.
If the outcome's mean is clearly curved in the inputs, the split carries no validated claim. The curved-mean follow-up (v5.2) failed and is parked (PARK_V5_2.md).

What it does

Give it two samples, period A and period B, each with inputs x (n × p) and an outcome y (length n). For each of the first four L-moments of y (location, scale, skewness, tail weight), it splits the A→B change into a composition piece (the inputs moved) and a response piece (how y reacts to the inputs changed). The two pieces sum exactly to the total change. All numerics run in the Rust core; Python only checks shapes and forwards.

Python

Entry point: traceot.explain_v5_1(x_a, y_a, x_b, y_b, *, n_y=256, k_lmoments=4, n_quad=64), defined in v5.py. It is exactly traceot.explain_v5(..., mean_model="ols"). Do not rely on the default: explain_v5 without mean_model runs v5 ("booster"), the version that failed its gate.

import numpy as np
import traceot

# Synthetic, neutral data: three inputs, a straight-line mean, skewed noise.
rng = np.random.default_rng(11)
n, p = 3000, 3
beta = np.array([1.0, -0.5, 2.0])
x_a = rng.normal(size=(n, p))
x_b = rng.normal(size=(n, p)) + np.array([0.5, 0.0, 0.0])  # only input 0 moves
y_a = 0.3 + x_a @ beta + rng.standard_exponential(n)
y_b = 0.3 + x_b @ beta + rng.standard_exponential(n)

r = traceot.explain_v5_1(x_a, y_a, x_b, y_b)        # TRACE_V5_1
# same call, spelled out:
# r = traceot.explain_v5(x_a, y_a, x_b, y_b, mean_model="ols")

comp, resp = r["lsplit_comp"], r["lsplit_struct"]   # one entry per L-moment
total = np.subtract(r["bb"]["lmom"], r["aa"]["lmom"])
for k in range(len(total)):
    print(f"lambda_{k + 1}: total {total[k]:+.4f} = composition {comp[k]:+.4f} + response {resp[k]:+.4f}")

This is the setup of the existing test test_explain_v5_1_ols_location in test_v5.py. That test asserts the budget is exact to 1e-10, the composition piece of λ1 is within 0.1 of 0.5 (the planted mean shift: 0.5 × coefficient 1.0 on input 0), and the response piece of λ1 is below 0.05 in absolute value. No other output values are claimed here; run it to see yours.

What comes back

  • lsplit_comp, lsplit_struct: lists of length k_lmoments, composition and response pieces for λ1…λk.
  • aa, ab, ba, bb: the four hybrids [covariates, conditional], each a dict with q_mix, q_bary, lmom, lmom_bary, mixing_residual.
  • u_nodes, y_grid: the quadrature nodes and support grid used.
  • seconds_fit, seconds_mixture, seconds_total; dropped_cols_a/dropped_cols_b (empty for the OLS path).

In the gate the inputs were centred on the average of the two period means before the call (centred in run_synthetic.py, used by run_v5_1_gate.py). Do the same to match the validated setup.

Rust

Entry point: traceot_core::trace::explain_v5 with ExplainV5Config { mean_model: LocationModel::Ols, .. }, defined in explain.rs. Returns an ExplainV5Report with the same fields as the Python dict.

use traceot_core::trace::{explain_v5, ExplainV5Config, LocationModel};

// x_a: n_a x p row-major, y_a: length n_a (same for period B).
fn split(x_a: &[f64], n_a: usize, y_a: &[f64],
         x_b: &[f64], n_b: usize, y_b: &[f64], p: usize)
         -> Result<(), traceot_core::TraceError> {
    let cfg = ExplainV5Config {
        mean_model: LocationModel::Ols, // TRACE_V5_1; the default is Booster (v5)
        ..ExplainV5Config::default()    // n_y = 256, k_lmoments = 4, n_quad = 64
    };
    let rep = explain_v5(x_a, n_a, y_a, x_b, n_b, y_b, p, &cfg)?;
    for k in 0..cfg.k_lmoments {
        let total = rep.bb.lmom[k] - rep.aa.lmom[k];
        println!("lambda_{}: total {total:+.4} = comp {:+.4} + resp {:+.4}",
                 k + 1, rep.lsplit_comp[k], rep.lsplit_struct[k]);
    }
    Ok(())
}

Before you trust a split

  • Check the linear-mean assumption yourself (for example, plot residuals against fitted values per period). The library does not do this yet; a report-only check is an open item, with no gating claim.
  • Only the pure-composition cells (skew_comp, tail_comp) were tested. Structure cells, coverage, ShiftBench, speed and per-feature shares are out of scope (PREREG_V5_1 §6).
  • Results in the gate: V5.1 gate page and V5_1_GATE_RESULTS.md.
