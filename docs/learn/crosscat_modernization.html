Modernizing CrossCat ideas for TRACE (Rust rebuild plan)

Plan only · 2026-10-26 (America/New_York) · technical detail in CROSSCAT_MODERNIZATION.md · prior review: bayesdb_crosscat.html

Decision framing (Jared, 2026-10-26 ET). This is an optimized rebuild of CrossCat’s generative model and inference surface — not a loose “inspired by” rewrite. The original probcomp/crosscat (+ thin bayeslite predictive hooks where needed) is the validation oracle: same synthetic / public-academic tables, same seeds where possible, documented tolerances on predictive queries, co-assignment, cluster structure, and likelihood-style checks. Rust must match the oracle first, then beat wall-clock and memory by a large margin. We still do not rebuild BayesDB as a product.

1. Why modernize

Last night’s review (BayesDB + CrossCat nighttime reading, merge 0258408) concluded the ideas are glass-box and TRACE-adjacent, but the C++/Cython/Python stack is bitrotted (Travis-era packaging; CrossCat master tip 2019-11-19; bayeslite tip 2020-04-16; bayeslite README warns of shifting behavior and insecure data handling). TRACE wants a Rust core with thin Python bindings, no neural nets, and methods that either are novel or match best rivals while being clearly faster. CrossCat’s factorial views × per-view row clusters are worth keeping as a TRACE-adjacent research track for mixture/composition attribution (views, \(\pi\), co-assignment) — as diagnostics / generative foil — not as a Bayesian database.

2. Timeless ideas vs dated machinery

Keep (timeless)Fix / replace (dated)
Outer column CRP (views) × inner row CRP per view; type-specific conjugates (JMLR §2) Single-site Gibbs engine (slow mixing; paper §2.6 local-minima warning)
Soft co-assignment / \(z\)-matrix dependence probabilities; context-sensitive row similarity Typing / hyper-prior layer glued to Python2-era heuristics; Travis packaging
Explicit category masses \(\pi\) as composition object; collapsed conjugates where possible Weak convergence diagnostics; hard posterior summarization / label switching
Efficient conditionals for simulate / densify once state is frozen Serialization, parallelism, numeric kernels; batch-table-only / no streaming story

Discard for TRACE scope: BQL DBMS, SQLite storage shell, MML product surface, any neural density heads. Keep bayeslite only as an optional oracle for a few predictive query shapes — not as runtime.

4. Target architecture

Rust core modules (planned, not implemented in this PR): model (generative + invariants) · suffstats (typed conjugate tables) · partition (CRP state, alignment helpers) · kernel (collapsed Gibbs, optional SAMS) · chains (parallel chains, diagnostics) · query (conditionals, co-assignment, \(\pi\)) · serde_state (reproducible dumps). Python: thin PyO3 surface for TRACE pre-flight diagnostics only. Oracle harness (separate path): pinned CrossCat/bayeslite container + parity suite.

What we will NOT build yet:

  • Full BQL / BayesDB DBMS, SQLite shell, or MML.
  • Neural nets / amortized encoders.
  • V5 \(Q_{\mathrm{mix}}\) scored suite (stays separate; this track is structure diagnostics).
  • Vendoring probcomp/crosscat or promised-ai/lace into the TRACE library crate without an explicit later ask.

5. Oracle parity protocol (rebuild gate)

Frozen reference commits (verified gh api 2026-10-26 America/New_York):

  • crosscat master tip 1f2ac5a43a50ebd7aaa89f0c5ac3815a170848c5 (2019-11-19 UTC) — Apache-2.0; 328★.
  • bayeslite tip 211e5eb3821a464a2fffeb9d35e3097e1b7a99ba (2020-04-16 UTC) — Apache-2.0; 942★; used only for optional predictive-query shapes.

Bitrot workarounds for the oracle: Docker/Podman image with pinned Python 3.x + numpy/Cython versions known to build that commit; run ./check.sh smoke first; never upgrade deps silently; record image digest in the parity log. If the tip will not build, stop and document — do not “fix” oracle math.

Quantities that must match (same table, same seed, same #chains/#iters when the oracle exposes them), within documented tolerances after label-alignment:

  1. Column co-assignment / dependence \(z\)-matrix (Frobenius or max-entry error).
  2. Within-view row co-assignment (or ARI / pairwise agreement after alignment).
  3. Category mass vectors \(\pi\) (sorted / Wasserstein-1 on weights) for composition views.
  4. Predictive: held-out conditional log score and/or imputation RMSE/0-1 on synthetic cells.
  5. Likelihood-style joint score of latent state under the shared generative density (JMLR §2.2), up to documented numerical tolerance.
Kill if parity fails: If after P1 budget (spec + two sampler iterations) the Rust core cannot meet the frozen tolerances on the synthetic partition suite, stop the rebuild. Options then are: (a) narrow to a TRACE diagnostic that only needs co-assignment approx quality without full CrossCat likelihood parity, or (b) evaluate depending on Lace as an external engine behind a TRACE API — both require an explicit ask. Do not quietly loosen tolerances to “pass.”

P0 is not V5 \(Q_{\mathrm{mix}}\). Keep Q_mix on its own board.

7. How we’ll know it worked

  1. Parity. Frozen synthetic partitions (known view/cluster truth) recover structure vs CrossCat within tolerances; no industry datasets.
  2. Speed / memory. Large-margin win vs CrossCat oracle on the same machine/image class; report Lace foil numbers honestly.
  3. TRACE usefulness. Co-assignment / \(\pi\) APIs change a pre-flight call on composition vs response feature blocks (synthetic).
  4. Falsifiers. Parity fail; speed stall; diagnostics no better than correlation; scope creep into BQL.

8. Risks & non-goals

  • Lace already exists (Rust PCC + Python; Gibbs/SAMS/Slice in lace_cc). Ignoring it would be dishonest; depending on it without ask would violate TRACE “Rust core we own” preference. Plan: foil + algorithm borrow first.
  • Label switching can fake “parity fail” — alignment protocol required.
  • Hyper-parameter grids in CrossCat are heuristic; P0 must freeze comparable grids.
  • Non-goals: BayesDB product, neural nets, streaming, industry data, merging foreign trees into traceot core, starting V5 Q_mix from this page.
